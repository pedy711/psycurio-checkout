# Decision record

Seven decisions that shaped the project, with the road not taken. Cuts for
time are listed at the end.

## 1. Money is integer cents; euro formatting is hand-rolled

**Decision:** the domain stores prices as `int` cents; `EuroFormatter`
produces `"7,47 €"` with plain arithmetic. Floats exist only at the inspector
boundary, rounded once.
**Rejected:** `decimal`/`float` prices with `CultureInfo`-based formatting.
**Why:** currency floats invite rounding drift, and culture-based formatting
depends on ICU data that IL2CPP stripping can break on device — a hand-rolled
formatter is deterministic in tests and identical on every platform. The cost
(no thousands separators) is irrelevant at grocery prices.

## 2. Scene, UI and content are generated by committed editor scripts

**Decision:** `Shop.unity`, the prefabs, materials, both UI canvases and all
component wiring are produced by idempotent editor scripts under
`Assets/Editor/`, runnable from the PsyCurio menu.
**Rejected:** hand-authoring the scene in the editor.
**Why:** the reviewer reads the git history; a hand-built scene is an opaque
YAML blob, while builder scripts are a reviewable floor plan, and the whole
project regenerates from code (proven when the cashier anchor moved: one
constant, full pipeline re-run). Honest cost: ~1,500 lines of builder code
that a hand-built scene wouldn't need.

## 3. Two assembly definitions, not a full split

**Decision:** only the domain and its tests get asmdefs; all scene scripts
stay in `Assembly-CSharp`.
**Rejected:** a per-layer asmdef partition (Interaction, Shop, Therapist, UI).
**Why:** the boundary that matters — no engine types in the rules — is
compiler-enforced by one `noEngineReferences` flag; further partitioning buys
compile-time isolation this project size never feels, at the price of
reference churn. Honest consequence discovered late: custom test assemblies
cannot reference `Assembly-CSharp`, so PlayMode tests were impractical and
runtime flows are verified manually (see cuts).

## 4. The session log writes after every rating, not only on exit

**Decision:** the JSON file is rewritten after each confirmed SUDS rating and
again on quit/pause.
**Rejected:** writing strictly once on exit, as the brief literally asks.
**Why:** on Android `OnApplicationQuit` is not guaranteed — the process can
be killed from the recents screen — and clinical data should survive a crash.
Writing per rating is a strict superset of the requirement at negligible cost.

## 5. The first-run hint returns every session

**Decision:** the hint shows at each Play start and fades on the first
successful interaction; no persistence.
**Rejected:** a PlayerPrefs "seen it" flag shown once per install.
**Why:** the people who launch this build are reviewers and clinicians, not a
retained player base — a once-ever hint would be invisible on every run after
the very first, which is exactly when someone else is watching.

## 6. The art pass is fully procedural, not imported

**Decision:** when the "make it beautiful" option was implemented post-core,
every model was built from parts or custom meshes in editor code and every
texture generated by `ProceduralTextures` — nothing imported except the
Mixamo character the brief itself prescribes.
**Rejected:** dressing the scene with CC0/free asset packs.
**Why:** zero licensing surface for a commercial submission, perfect
reproducibility from the repository, and consistency with the project's
everything-is-reviewable-code pipeline. Honest cost: procedural art has a
ceiling — a texture artist beats this look in an afternoon; the point is
what the pipeline demonstrates, not gallery quality.

## 7. Items fly; the cashier does not fetch them

**Decision:** of the two remaining effect options, the shelf-to-counter
flight (option 2) was implemented in full and the walking-cashier option 3
deliberately skipped — a skip by design, not by time.
**Rejected:** implementing both, or preferring the walk.
**Why:** both options prescribe a placement fiction for the *same click* —
an item cannot fly itself to the counter while the cashier also walks over
and carries it. And fetching costs seconds of animation per placement,
which fights the task's stated core priority: a checkout loop that stays
responsive. The flight keeps placement fast and adds the required
particles-and-sound feedback.

## Cut for time

- **PlayMode automated tests** — blocked by decision 3; the runtime loop is
  verified by a scripted edit-mode harness plus a manual acceptance walk.
- **Balloon tail** — the speech bubble has no pointer to the speaker; position
  above her head carries the attribution.
- **Localization** — all patient-facing strings are English and hardcoded;
  the narrator is one class, so a German sentence set is a contained change.
- **Placement/removal animation** — items appear and vanish in one frame;
  audio carries the feedback.
- ~~**Distinct bystander models** — all three queue figures share one
  mannequin prefab.~~ Resolved post-core: three distinct Mixamo characters
  with rebuilt URP materials, a shared retargeted idle at randomized phase,
  and measurement-solved queue positions (the anchors are placed by
  projecting rendered body centers to screen columns, because idle poses
  sway bodies off their anchors).
