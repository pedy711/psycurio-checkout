# PsyCurio Checkout — Hiring Task

A mouse-driven shop checkout scene for therapist-guided social-exposure work:
a shelf of groceries, a counter, a cash register and a cashier who watches,
waves and speaks — plus a therapist control panel with live exposure-intensity
controls and SUDS logging.

![Patient view](docs/images/patient-view.png)

## How to run

- **Unity 6000.3.21f1 LTS** (Universal Render Pipeline). Open the project,
  open `Assets/Scenes/Shop.unity`, press **Play**.
- Everything is mouse-driven: click shelf items to put them on the counter,
  click a counter item to put it back, click the cashier to be greeted, click
  the register to hear your total. **T** or the **Therapist** button (bottom
  left) toggles the therapist panel;
  **Reset counter** clears the purchase.
- Android build: `Builds/psycurio-checkout.apk` (IL2CPP, ARM64, min API 25),
  or rebuild via **PsyCurio > Build Android APK**. Install with
  `adb install psycurio-checkout.apk`; taps behave like clicks and the app
  locks to landscape, matching the fixed camera's framing. Verified on a
  Galaxy S21 Ultra.
- Tests: **Window > General > Test Runner > EditMode > Run All**
  (37 tests over the domain layer).

## What was built

**Core:** shelf with six ScriptableObject-defined groceries; five-slot counter
with an explicit, visibly-refused limit; Mixamo cashier with idle and
click-triggered wave; register click makes her state the chosen items
(duplicates grouped: "2x Coffee") and the euro total in a speech balloon.

**Additional tasks** — the chosen one first, per the sheet's "choose one!":
the final option ("suggest your own addition"), with "Add Unit tests" also
covered in full by the 37 EditMode domain tests. After the core was complete
and tagged `core-complete`, the remaining feasible options were implemented
as extensions — items fly from shelf to counter with a landing burst and
generated sound (option 2), and a full art pass with modeled items and
procedural textures (option 1). The walking option was deliberately skipped:
it prescribes a different placement fiction for the same click as the flight
and would cost seconds of latency per placement (see `docs/DECISIONS.md`).

The centerpiece addition: a therapist control panel (T) with live
exposure-intensity controls — cashier eye contact, response delay, bystander
count, ambient noise level — plus a patient-facing SUDS prompt (0–100)
triggered from the panel. Every rating appends
`{ timestamp, suds, settings snapshot, items on counter }` to a per-session
JSON in `Application.persistentDataPath/sessions/`.

## Usability decisions

- **Hover highlight + cursor change appear only on genuinely clickable
  objects** — nothing inert may look interactive, so trust in the affordance
  stays absolute.
- **No silent clicks anywhere**: placement ticks, removal tocks, a refused
  sixth item pulses the slot markers red *and* gets a spoken refusal *and* a
  buzz, and a click that hits nothing plays a soft tap — failure is
  information, not absence.
- **Clicking a counter item removes it** — a mis-click needs a one-click undo,
  not a reset.
- **Reset is quiet** (small, bottom-right) — recoverability shouldn't compete
  with the scene for attention.
- **The first-run hint fades on the first successful interaction** and returns
  each session — a once-ever flag would hide it from every later reviewer.
- **The speech balloon replaces, never stacks**, shows for reading time scaled
  by message length, billboards to the fixed camera, and auto-sizes — verified
  against the longest possible sentence.
- **Response delay applies to speech only** (the wave stays instant): social
  response latency is the exposure stimulus; interaction feedback must stay
  responsive or the scene feels broken rather than uncomfortable.
- **The SUDS slider opens at the neutral midpoint** so every rating is the
  patient's own movement, not an accepted default.
- **Bystanders are deliberately inert** — no highlight, no cursor change —
  social presence without false affordance.

## Architecture

Shop items are ScriptableObjects (`Assets/Items/`): a clinician or content
designer adds or reprices products entirely in the Inspector — no code, no
programmer in the loop. All shop rules live in `PsyCurio.Shop.Domain`, an
assembly with **no engine references**, enforced by the compiler: the basket,
narration and session-record logic that defines the therapy content is
portable to a server, an analysis pipeline, or a future non-Unity client
unchanged, and is covered by 37 fast EditMode tests. Every click flows
through one `ClickRouter` dispatching to an `IClickable` interface, so
interaction behaviour is consistent by construction and a future input method
(gaze, controller, touch) means changing one class, not auditing every
object. The scene, UI and content are generated by committed editor scripts
(`Assets/Editor/`) — layout and wiring are reviewable code, reproducible from
the repository, and positions live only in named anchor transforms. That
extends to the art: every model is built from parts or custom meshes in code
and every texture (wood, tiles, labels, skins) is generated and saved by
`ProceduralTextures` — original assets in the most literal sense, with no
licensing questions anywhere in the project.

## The therapist layer, clinically

The panel implements graded exposure: the clinician titrates
social-evaluative load — being watched (eye contact), awkward silence
(response delay), audience (bystanders), sensory load (noise) — live, without
breaking the patient's task. Each SUDS rating is stored with a frozen
snapshot of exactly that stimulus configuration and the task state, so a
session file is the beginning of an outcome dataset: distress over time *as a
function of* exposure intensity, comparable across sessions and patients.

## Process

Thirteen reviewed steps, one conventional commit each, tagged
`core-complete` after the core brief; `docs/DECISIONS.md` records the five
significant trade-offs and what was cut for time. Development was
AI-assisted; `docs/AI-LOG.md` is the candid, dated log of everything the AI
got wrong along the way and how each mistake was caught.
